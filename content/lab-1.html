Цель работы

Исследовать три программы обработки серверных журналов, не описанные в лекции: Visitors, lnav и W3Perl. Сравнить их по источникам данных, способу настройки и результатам анализа. Работа представляет обзор документации; программы не устанавливались и результаты обработки реального журнала не заявляются.

1. Источник внутренней статистики

При запросе ресурса веб-сервер записывает строку в access log. Обычно она содержит время, адрес клиента, метод, URL, код ответа, размер ответа, Referer и User-Agent. Анализатор разбирает строки, отбрасывает ненужные записи, группирует запросы и рассчитывает показатели. Это позволяет исследовать посещаемость и одновременно искать ошибки сервера.

203.0.113.10 - - [06/Oct/2026:12:30:00 +0300] "GET /lab-1.html HTTP/1.1" 200 3421 "-" "ExampleBrowser/1.0"

Листинг 1 — искусственная строка журнала: адрес взят из диапазона для документации. Это пример структуры, а не запись посетителя сайта.

Из одной строки можно определить успешность запроса и объём ответа. Нельзя достоверно определить возраст человека, факт прочтения текста или длительность последней страницы сеанса. IP-адрес также не равен отдельному человеку: пользователи могут разделять адрес, менять сеть или пользоваться несколькими устройствами.

2. Выбранные программы

Visitors

Разработчик — Salvatore Sanfilippo. Официальная страница распространяет исходники по GPL; готовые Windows-сборки имеют отдельные условия. Программа на C рассчитана на Linux, Windows и Unix-подобные системы. Интерфейс — командная строка, результаты — текст и самостоятельный HTML-отчёт. Настройки передаются аргументами: файлы журнала, фильтры, число строк в отчёте, дополнительные разделы.

Выводит запрошенные страницы, источники переходов, оценки уникальных посетителей, распределение запросов по времени, браузеры и ошибки 404. Пути переходов могут отображаться через Graphviz. Преимущества: простой пакетный запуск и отчёт без внешних ресурсов. Недостатки: старая версия 0.7, ограниченное распознавание современных браузеров; поисковые фразы часто отсутствуют в современных Referer.

lnav — Log File Navigator

Автор — Timothy Stack, лицензия BSD-2-Clause. Официальный сайт и репозиторий описывают сборки для Linux, macOS и Windows; имеются пакеты FreeBSD. Это интерактивный терминальный просмотрщик, пригодный для исследования access log, а не готовый маркетинговый кабинет.

lnav распознаёт форматы журналов, объединяет записи по времени, поддерживает поиск, фильтры и SQL-запросы. Дополнительные форматы задаются JSON-описаниями. После запроса таблицу можно выгрузить в CSV или JSON. Для веб-аналитики можно самостоятельно рассчитать число запросов по URL, кодам ответа и времени. Сильная сторона — проверка конкретных записей и гибкие запросы; ограничение — показатели посещаемости и сеансы нужно определить самостоятельно, красивый HTML-дашборд не является основным результатом.

W3Perl

Проект W3Perl ведёт Domisse, автор официального блога проекта. Официальный сайт предлагает свободную программу на Perl по GPL. Документация рассматривает Unix/Linux, macOS и Windows. Анализируются журналы веб-сервера и других служб; результаты публикуются в HTML. Интерфейс настройки может быть веб-формой, выполнение анализа — командами и по расписанию.

Для запуска задают расположение журналов, их формат, каталог отчётов и параметры фильтрации. Доступны отчёты о страницах, источниках, ошибках и активности во времени; дополнительные возможности зависят от конфигурации и модулей. Преимущество — регулярные отчёты и несколько типов журналов. Недостаток — устаревшая ветка: на странице загрузки указана версия 3.20 от июня 2015 года. Совместимость старых Windows-инструкций с текущей системой требует отдельной проверки.

Применение в России. Все три инструмента могут обрабатывать локально уже полученный журнал без облачного аккаунта. Это техническое основание для автономного применения, а не гарантия доступности каждого зеркала, оплаты сборки или поддержки. Загрузка и установка из российской сети в этой работе не проверялись. Для Visitors можно использовать свободные исходники; покупка готовой сборки не выполнялась.

4. Пример настройки

# Visitors: обработка существующего журнала, пример из документации
visitors -A -m 30 access.log -o html > report.html

# lnav: открыть локальный журнал для интерактивного исследования
lnav access.log

Листинг 2 — команды для самостоятельного воспроизведения; в рамках обзора не запускались.

Перед анализом нужно установить формат, часовой пояс, период и правила исключения ботов. Затем сверить несколько исходных строк с итоговыми таблицами. На GitHub Pages владельцу сайта не выдаётся access log веб-сервера, поэтому практический сбор посещений этого стенда выполняется внешними счётчиками в работах №3–5. Для запуска внутреннего анализа нужен собственный веб-сервер либо предоставленный журнал.

5. Контрольные вопросы

  1. Три определения веб-аналитики. В лекции это сбор, измерение и анализ поведения для улучшения работы сайта. С технической точки зрения — превращение событий и запросов в показатели и отчёты. С управленческой — проверка решений и гипотез по измеримым результатам. Последние два определения являются рабочими формулировками автора отчёта.
  2. Виды систем сбора. Серверные журналы, внешние счётчики и собственный программный сбор событий. Комбинация источников помогает объяснять расхождения.
  3. Примеры внутренних программ. Visitors формирует веб-отчёт, W3Perl обновляет отчёты по расписанию, lnav позволяет исследовать отдельные записи и SQL-агрегаты. В лекции также описаны AWStats и Webalizer.
  4. Главный источник поведения при анализе серверных логов. Access log с последовательностью HTTP-запросов. Для ошибок дополнительно используют error log. Клиентские действия без сетевого запроса в него не попадают.
  5. Что такое лог-анализатор? Программа, которая разбирает записи журнала, фильтрует и группирует их, затем формирует показатели или результаты поиска.
  6. Преимущества и недостатки внутренней статистики. Она учитывает запросы без JavaScript, полезна для ошибок и нагрузки и хранится под контролем владельца. Ограничения: кэш, боты, неоднозначность идентификации, отсутствие экранных действий и сложность определения сеансов.

Вывод

Для быстрого самостоятельного HTML-отчёта подходит Visitors; для поиска причин конкретных ошибок и гибких выборок — lnav; для изучения регулярной серверной отчётности — W3Perl. Устаревшие программы полезны как примеры подходов, но перед эксплуатацией требуют проверки совместимости. При выборе инструмента важнее доступность исходного журнала и нужные показатели, чем число графиков.
